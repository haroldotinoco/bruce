# Opportunity SaaS — Technical

## 1. Technical objective

**Opportunity SaaS** should be implemented as an independent service, responsible for generating, structuring, qualifying, and prioritizing venture opportunities in a reusable manner within and outside Bruce.

It should be consumable as:
- an internal module of the ecosystem;
- a standalone product.

---

## 2. Architectural role

Within the ecosystem, Opportunity SaaS is a **discovery and prioritization service**.

It occupies the initial position in the venture creation flow and should be treated as a provider of structured hypotheses.

Its primary technical responsibility is to transform context inputs into **normalized Opportunity Briefs**.

---

## 3. Technical responsibilities

The service should be responsible for:

- receiving discovery context;
- executing structured reasoning;
- producing consistent opportunities;
- calculating or inferring scoring;
- classifying priority;
- persisting results;
- making outputs available to subsequent modules.

---

## 4. Primary entity

### Suggested fields

- `_id`
- `title`
- `summary`
- `problem`
- `targetAudience`
- `contextWhyNow`
- `valueHypothesis`
- `solutionAngles`
- `signals`
- `initialRisks`
- `score`
- `priority`
- `status`
- `sourceContext`
- `recommendedNextStep`
- `createdAt`
- `updatedAt`

---

## 5. Possible statuses

An `Opportunity` can assume states such as:

- `generated`
- `qualified`
- `prioritized`
- `promoted`
- `discarded`

---

## 6. Score and priority

The service should be able to assign at least:

### Score
Numeric or semi-structured value that represents the strength of the opportunity.

### Priority
Operational range used by Bruce, for example:
- `high`
- `medium`
- `low`

---

## 7. Input contract

The service should accept a flexible discovery payload.

### Conceptual example of input

```json
{
  “goal”: “discover opportunities”,
  “theme”: “fintech”,
  “audience”: “micro and small businesses”,
  “constraints”: {
    “geography”: “Brazil”,
    “businessModel”: “B2B SaaS”
  },
  “context”: {
    “whyNow”: “Pix adoption, financial digitization”
  }
}
```

## 9. Suggested endpoints

## 9.1. POST /opportunities/run

Executes the primary discovery flow.

### Responsible for:

- generating new opportunities;
- qualifying them;
- returning structured output.

- - -

## 9.2. POST /opportunities/score

Re-evaluates existing opportunities.

### Responsible for:

- recalculating score;
- updating priority.

- - -

## 9.3. POST /opportunities/promote

Marks an opportunity as fit for the next stage.

### Responsible for:

- promoting to Venture SaaS;
- recording stage transition.

- - -

## 9.4. GET /opportunities/:id

Queries a specific opportunity.

- - -

## 9.5. GET /opportunities

Lists opportunities by filters.

Filter examples:

- status
- priority
- score
- theme
- createdAt

- - -

## 10. Persistence

The service should persist:

- generated opportunities;
- scoring history;
- promotion or discard status;
- original generation context;
- timestamps.

- - -

## 11. Produced artifact

The primary technical artifact generated by this service is:

## OpportunityBrief

This artifact should be storable, versionable, and reusable.

### Expected fields

- metadata
- generation context
- opportunity structure
- score
- priority
- recommendation

## 12. Expected integrations

## 12.1. Bruce Core

Should be able to trigger the service to generate new opportunities.

## 12.2. Venture SaaS

Should consume promoted opportunities.

## 12.3. Portfolio / Governance

Can use score and priority for allocation decisions.

## 12.4. Shared Memory

Can absorb aggregated patterns of relevant opportunities over time.

## 14. Technology stack

### Orchestration

| Component | Technology |
| ---------- | ---------- |
| **Backend** | Node.js / NestJS |
| **Database** | MongoDB (Mongoose) for opportunities, scoring history, generation context |
| **Job Queue** | BullMQ (Redis-backed) for async discovery jobs |
| **Storage** | S3-compatible for exported opportunity reports |

### AI Services

| Service | Role |
| ------- | ----- |
| **OpenAI API** | Reasoning, structured opportunity generation, scoring |
| **OpenAI Structured Outputs** | JSON Schema enforcement on all outputs |
| **Web Search (optional)** | Market research, trend signals, competitor context |

---

## 15. Non-functional requirements

The service should be:

- reusable;
- auditable;
- decoupled;
- compatible with standalone execution;
- capable of operating with multiple input contexts;
- oriented toward structured output.

- - -

## 16. Technical success criterion

Opportunity SaaS is technically successful when:

- it can transform context into structured opportunities;
- it generates stable and consistent outputs;
- it integrates easily with Venture SaaS;
- it enables reliable ranking and prioritization;
- it helps Bruce decide what deserves to advance.
